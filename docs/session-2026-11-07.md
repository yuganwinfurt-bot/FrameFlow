## 二、起点诊断：接手时的问题

先跑基线，再动代码，避免「改完不知道原来坏在哪」。

### 2.1 用测试说话

```
python -m unittest discover -s tests -v
→ Ran 28 tests, 3 failures（33.5s）
```

三个失败都不是环境问题，而是**功能改了测试没跟**：

- `test_video_editor_frame_cut_paste_save_and_queue` 期望三个页签，实际多了一个新增的「文件详情」页；
- 音频 / 图片编辑器里 `tabs.count()` 断言 1，实际是 2。

结论：交付前测试是挂的。修法是把断言对齐到新行为（保留「文件详情」页），而不是删功能。

### 2.2 界面在真实窗口尺寸下是坏的

在 1368×960（Windows 125% 缩放，逻辑约 1094×768）下截图，右栏出现**文字重叠**：

- `QPlainTextEdit#fileDetails` 用了 `setFixedHeight(148)`，纵向空间不够时不会压缩，Qt 布局溢出，把「视频分辨率」那行压到了「分辨率」标签上；
- 编辑页内容撑出窗口，被裁掉一截。

根因不是"窗口太小"，而是**固定高度 + 没有滚动容器**。所以修法是给属性栏加滚动区，而不是把窗口调大。

### 2.3 气质不对：像网页，不像客户端

- 大圆角卡片流 + 常驻虚线拖放区 + 满宽进度条，是典型的网页仪表盘；
- 信息密度低：文件列表没有列头，没有时长 / 大小列；
- 配色散落：15 处 `#175bbc`、12 处 `#53677e`…… 全写死在各个文件里；
- `motion.py` 里还留着一段无人使用的 `studioControl` 深色分支，说明设计方向换过但没清干净。

## 四、按反馈改造清单

### 4.1 结构

- **删掉菜单栏**。「文件 / 帮助」整条不要，Ctrl+O / Ctrl+Q 作为 `QAction` 挂在窗口上，快捷键保留但不占版面。
- **删掉右上角两个标签**。「FFmpeg 就绪」只在**真的找不到** ffmpeg 时以红字出现；「全部在本机处理」并进空队列那句副标题。
- **删掉工具栏行**。「＋ 添加」进入队列卡片表头（「批量格式」「清空列表」之前），队列非空才显示；空队列时入口是中间那块投放区。
- **编辑设置按页签分工**：视频帧页 = 剪辑区间 + 视频导出；音轨页 = 选区 + 音频导出；图片页 = 图片格式 / 画质 / 分辨率。同一时刻只显示这一页用得上的东西。
- **取消任务 / 返回转换**从底部条搬进「编辑设置」标题行右侧；底部只剩日志和进度条，「运行信息」四个字删掉。
- **导出补分辨率与目标体积**：视频导出新增「最长边」（原始 / 1920 / 1280 / 854）与「目标体积」（KB，0 为不限），并且**真的生效**（见 4.3）。

### 4.2 视觉

- 新建 `frameflow/theme.py`：一套设计标记（背景 `#F3F3F3`、卡片 `#FFFFFF`、边框 `#E0E0E0`、主色 `#0F6CBD`、圆角 8px），主窗口与编辑工作台共用；顺带做了 `app_icon()` / `brand_mark()`，程序第一次有了自己的图标。
- 文件列表从"卡片流"改成**带列头的表**：缩略图 / 名称 / 时长 / 大小 / 状态 / 输出格式，列宽常量表头与行共用，滚动条出现时表头同步让位。
- 状态从纯文字改成**胶囊标签**（就绪 / 转换中 / 已完成 / 失败 / 已取消各有配色）。
- 满宽进度条改成底部 6px 细条，百分比写进状态行。
- 编辑工作台的页签从"蓝色药丸"改成**下划线式**，与主窗口的导航一致。
- 标题栏白底 + 一条分隔线，撑起 chrome 感。
- 文件详情对话框：淡蓝速览带（缩略图 + 16px 标题 + 一行概要）、主色数字的四个指标块、带分隔线的页脚。
- 窄窗口适配：宽度 < 1120 像素时先隐藏「大小」列、属性栏 352→300，把宽度让给文件名。

### 4.3 能力

- **编辑导出支持缩放与目标体积**。`editing._graph()` 增加 `scale` 滤镜（按最长边等比缩到偶数边），`render_edit()` 增加与主界面同源的码率逼近：按片段时长反推码率，最多三轮，取最小且不超限的结果。
- **文件详情重做**为独立窗口（主界面）与两列视图（编辑器内），字段来自 `media.detail_rows()` 的分组结构，逐行可复制。

## 五、关键决策与理由

| 决策 | 备选方案 | 为什么这么选 |
| --- | --- | --- |
| 属性栏「外层卡片固定 + 内部滚动」 | 整块卡片放进 QScrollArea | 外层滚动会把底部操作按钮一起卷走；内部滚动能让「编辑 / 预览」「打开成品」始终可见 |
| 文件详情从**内联折叠**改成**独立窗口** | 在 352px 属性栏里就地展开 | 内联展开必然被底部按钮遮住（实测两组字段叠在一起），窗口才装得下四层信息 |
| 详情用**分组字段 + 指标块** | 继续用一列 `名称：值` 文本 | 纯文本没有层次，扫读要靠找；指标块把「时长 / 大小 / 分辨率 / 帧率」提到最上面 |
| 尺寸单位统一成**十进制**（1e3 进位） | 1024 进位 | 队列里的 `file_size()` 已经是十进制，同一个文件不能显示 6.5 KB 和 6.7 KB 两个数 |
| 探测不到的字段**直接不显示** | 显示「未知」 | 音频页曾经半屏「未知」，那不是信息量，是噪音 |
| 添加文件**收进表头** | 保留工具栏 | 操作应该贴着它作用的对象；工具栏一行只放一个按钮性价比太低 |
| 自绘 `SpinBox` | 继续用 QSS 调箭头 | QSS 的箭头只能贴图片，写死尺寸后就是两个空方块；自绘能拿到真实按钮矩形，悬停反馈也能做 |
| 启动入口**只留项目内的 .lnk** | 桌面快捷方式 / .bat | 用户要的是"打开文件夹双击"，多一个入口就多一份困惑 |

**踩过的坑（值得写下来）**：

1. `deleteLater()` 不是立刻生效——切换文件时旧控件仍按旧几何绘制，两组字段会叠在一起。改成 `hide()` + `setParent(None)` 再 `deleteLater()`。
2. `QRectF(pixmap.rect())` 是**设备像素**：125% 缩放下 130×80 与逻辑 104×64 差一圈，圆角裁剪会落到画面外。要用 `width()/devicePixelRatio()` 换算。
3. `QScrollArea` 的视口不继承透明背景，要 `viewport().setAutoFillBackground(False)` + 透明样式。
4. `setMinimumWidth(0)` 不生效，Qt 的 `qSmartMinSize()` 会退回布局最小宽度（差 1px 就会裁掉按钮右边）；`setMinimumWidth(1)` 才会采用。
5. 编码参数**拼重复**：编辑导出第一版把 `_ENCODERS` 加了两遍，后者覆盖前者，`-b:v` 被 `-crf` 顶掉，目标体积完全不起作用，只有跑冒烟测试才发现。
6. Windows 批处理**必须是 CRLF**，LF 换行会把整个文件当成一行执行，报 `'n。' is not recognized`。
7. 快捷方式里存的是**绝对路径**：项目被复制到别处时，`.lnk` 仍然指向老目录——这次的"改了没生效"就是这么来的。

## 八、复盘

**做对的**：

- 先取证再动手。三个失败用例 + 一张重叠截图，让后续每一处改动都有依据。
- 用设计标记（`theme.py`）一次收口，而不是继续往各处塞十六进制颜色。
- 修一个记一个：每个决定都写清"为什么不是另一个方案"，包括被推翻的（内联详情）。
- 改界面时保住测试依赖的属性名（`window.jobs`、`row.format`、`editor.tabs` 等），重写布局没把测试写崩。

**走过的弯路**：

- 文件详情先做成内联折叠，做完才发现 352px 根本装不下，白改一轮。教训是**先量可用空间，再定形态**。
- 启动方式先加 .bat 又加桌面快捷方式，开发者实际只想要文件夹里那一个。教训是**入口越少越好**，加之前先问一句。
- 目标体积第一版拼错编码参数，"界面上有、实际不生效"比"没有"更糟。教训是**新增能力必须跑端到端冒烟**。

**如果重来**：会先花十分钟问清楚"你平时怎么启动、想看哪块"，再动手改界面——这次的返工基本都出在"信息不对称"上，而不是技术难度上。

## 九、视频帧界面二次调整（开发者反馈）

### 开发者反馈

- 「界面这么素」；视频帧页看起来不像播放器。
- 需要让媒体参数直接可见，并补上清晰的右侧剪辑、导出操作；按钮也需要更有层次。
- 第四张图是设计参考图，不是 FrameFlow 当前界面。实现时按它的播放器、媒体检查器和设置栏层级取意，不把参考图里的产品名和布局当作项目现状。

### 设计决策与实现

1. **把视频画布做成播放器。** 深色画面区上方显示实际文件扩展名、编码、分辨率和帧率；下方放上一帧、播放/暂停、下一帧、可拖动进度和当前/总时间。控制条与时间线共用同一帧游标，避免两套位置不同步。
2. **媒体信息常驻。** 在时间线下方放分辨率、帧率、时长、大小、视频编码、码率、像素格式和音轨信息；更完整的字段仍可在「文件详情」查看。
3. **右栏按任务分组。** 剪辑区间和导出选项显示在右侧设置栏，保存动作固定在滚动区之外，小窗口下也能直接保存。栏宽下限设为 360 像素，避免音轨页切换时设置栏忽宽忽窄。

## 十、媒体栏、输出位置与蓝色主题（二次反馈）

### 开发者反馈

- 播放器横向空间还要更大，视频画布可以降低一点高度。
- 不需要持续显示“第几帧”；时间线缩略图底部也不要再占一条帧号文字。
- 时间线下面有空白带；媒体信息可以放到右侧编辑设置上方并压缩高度。
- 输出位置要有清楚的文件名和目录；缺少视频编码硬件加速选项。
- 界面主色指定为蓝、浅蓝、深蓝。

### 设计决策与实现

1. **媒体信息移至右栏顶部。** 视频编辑栏顶部使用 2 列 × 3 行紧凑卡片，显示分辨率、帧率、时长、大小、视频编码和音轨；完整参数仍在「文件详情」页。右侧默认宽度缩到 300 像素，为播放器和时间线留更多宽度。
2. **隐藏当前帧序号与缩略图标签。** 播放器保留播放时间码和拖动进度；时间线缩略图只显示画面，选区说明只显示帧数和段数，起止帧输入仍可精确剪辑。
3. **收起空闲状态空间。** 进度条所在行只在导出任务运行时显示；空闲底部状态栏收至约 30 像素，长信息仍可拖动分隔线查看。
4. **按要求改成蓝色系。** 全局工作区底色改为浅蓝灰，卡片保持白色、文字改为深蓝；播放器采用深海军蓝底、浅蓝信息卡和蓝色播放/进度强调，替换原来的橙色强调色。
5. **输出位置成为可操作卡片。** 转换页和编辑页均显示预期输出文件名与目标目录，目录按钮可直接选择位置；已存在同名文件时继续沿用自动加序号保护策略。
6. **硬件加速接入真实编码器。** 根据当前 FFmpeg 的 `-encoders` 结果列出 NVENC、AMF、Quick Sync 或 MediaFoundation；选项按格式过滤。设备或驱动不能用时提示并自动用 CPU 软件编码，取消任务则不会触发回退。
